1. Abstract

The course project titled “Design and Development of a Smart Hospital Bed Allocation and Patient Flow Management System (MediPulse Flow)” presents the comprehensive engineering, architectural modeling, and deployment of a responsive, full-stack hospital operational intelligence web application. In contemporary healthcare facilities, manual bed management and disconnected departmental coordination lead to severe emergency department boarding, prolonged patient wait times, sub-optimal bed turnover rates, and clinical triage risks. MediPulse Flow eliminates these administrative bottlenecks by providing an automated, priority-driven smart bed allocation engine coupled with an interactive four-stage Kanban patient workflow board.

The system is developed with a strict, lightweight technology stack ensuring high performance and local self-sufficiency. The frontend client is built using semantic HTML5, modern CSS3 (featuring a clinical healthcare palette: Primary Navy Blue #163A5F, Accent Teal #13A89E, and Light Grey #F4F7FA), and modern TypeScript / Vanilla JavaScript (ES6+), communicating asynchronously with backend endpoints via the native Fetch API. Real-time hospital analytics and distribution metrics are visualized using Chart.js and styled with Lucide Icons. The backend is engineered on Node.js and Express.js in strict TypeScript, exposing RESTful endpoints for patient directory management, visual ward beds, inter-ward transfers, and clinical workflow transitions. Data persistence is managed through an in-memory synchronized JSON storage engine (mockData.json) pre-configured with a realistic dataset of 250 hospital beds across five clinical wards (General Ward, ICU, Emergency, Private Ward, Pediatric Ward) and 193 patient records (including 15 patients in an active triage queue).

Key innovations include a deterministic triage allocation algorithm prioritizing Emergency patients, atomic bed transfers that prevent allocation conflicts, a four-stage Kanban workflow (Waiting $\rightarrow$ Admitted $\rightarrow$ Under Treatment $\rightarrow$ Ready for Discharge), and automated discharge protocols that immediately release beds, timestamp sanitization, and dynamically recalculate census metrics. The application passed an automated end-to-end integration test suite with a 100% success rate and is maintained under Git version control on GitHub.

2. Introduction

Inpatient bed availability is one of the most critical determinants of healthcare operational efficacy and patient clinical outcomes. When emergency departments experience overcrowding, delays in bed allocation lead to prolonged boarding, patient dissatisfaction, heightened clinical risks, and administrative burnout. Conventional hospital information systems often rely on static tabular databases, manual phone coordination, or physical whiteboards, resulting in significant communication latency between emergency triage, ward nursing stations, and housekeeping staff.

MediPulse Flow is conceived as a modern, real-time command center designed to optimize hospital operational velocity. By combining automated triage rules, visual color-coded ward management, and Kanban-style workflow progression, the platform ensures that critical patients receive expedited placement into appropriate wards while administrators maintain real-time visibility over hospital census and turnover rates.

2.1 Problem Statement

Healthcare facilities face severe operational friction due to systemic inefficiencies in patient flow and bed management:

  1. Emergency Boarding & Triage Delays: Patients requiring urgent inpatient care wait for extended periods in emergency corridors due to lack of real-time visibility into bed vacancies across specialized departments.
  2. Absence of Acuity-Based Allocation: Manual allocation workflows often process admissions on a first-come, first-served basis, resulting in non-critical patients occupying high-acuity beds needed for emergency cases.
  3. Inter-Ward Transfer Friction: Transferring recovering patients from intensive care to general wards involves manual coordination that frequently causes unrecorded vacancies or double-booking.
  4. Turnover Lag (Ghost Beds): When patients are discharged, hours often elapse before housekeeping is notified, causing beds to sit idle while triage queues lengthen.
  5. Lack of Dynamic Real-Time Analytics: Hospital leaders lack instantaneous dashboards showing dynamic occupancy percentages, daily admission/discharge velocity, and bed turnover rates calculated from live census data.

2.2 Objectives

The primary engineering objectives of the project are:

  • Rule-Based Smart Allocation: Implement an automated triage algorithm that prioritizes Emergency and High-priority patients, matches target clinical departments, verifies bed availability, and updates patient status to Admitted.
  • Four Specialized Operational Interfaces: Build responsive, modern interfaces for Dashboard Analytics, Patient Directory CRUD, Visual Bed Management, and Patient Flow Kanban.
  • Synchronized RESTful Architecture: Construct a modular Express.js backend using TypeScript with standardized JSON response contracts and robust error handling.
  • Dynamic Census Recalculation: Ensure that all hospital metrics (Total Beds, Available Beds, Occupied Beds, Waiting Patients, Occupancy Rate) recalculate dynamically upon any clinical mutation.
  • Zero External Database Overhead: Persist all clinical data to a synchronized JSON storage engine (mockData.json), ensuring standalone local execution with zero database configuration.

2.3 Scope

The project scope encompasses the complete design, implementation, automated verification, local deployment, and GitHub version control of MediPulse Flow. The system tracks 250 hospital beds across five departments (General Ward, ICU, Emergency, Private Ward, Pediatric Ward) and four operational states (Available, Occupied, Maintenance, Reserved). Out of scope for this release are external billing payment gateways, biometric smart locks, and multi-hospital regional network clustering.

4. System Analysis

4.1 Existing System

In prevailing healthcare administration across many regional and community hospitals, bed management is handled through manual phone calls, dry-erase whiteboards at nursing stations, or unlinked spreadsheet logs (such as Microsoft Excel). When an emergency patient requires admission, the triage nurse contacts the central admission coordinator, who sequentially telephones ward supervisors across the hospital to check for vacancies.

Critical Bottlenecks of the Existing System:

  • Severe Communication Latency: Manual bed queries cause delays of 45 to 90 minutes before a vacant bed is identified and prepped.
  • Absence of Acuity Triage: Admissions are processed chronologically rather than by medical urgency, causing high-priority emergency cases to wait behind non-urgent elective admissions.
  • Double-Booking & Allocation Conflicts: Unsynchronized spreadsheets and shift changes frequently cause multiple nurses to assign different patients to the same bed.
  • Turnover Lag (Ghost Beds): Beds vacated by discharged patients often remain marked as occupied for hours until manual paperwork is processed, leaving clean beds unavailable to triage.
  • Lack of Real-Time Management Oversight: Hospital executives have no live visibility into occupancy percentages, ward bottlenecks, or bed turnover metrics.

4.2 Proposed System

MediPulse Flow replaces fragmented manual tracking with a centralized, real-time digital command center. By combining an automated allocation engine, interactive visual ward maps, and a Kanban patient flow pipeline, the system transforms bed management into a deterministic and transparent process.

Feature Existing Manual System Proposed MediPulse Flow System
Bed Visibility Fragmented whiteboards, phone calls, static spreadsheets Real-time visual grid color-coded across all 250 beds
Allocation Method Manual, arbitrary, first-come first-served Automated rule-based prioritization (Emergency > High > Med > Low)
Allocation Latency 45 to 90 minutes per admission Sub-second automated matching and assignment
Patient Transfers High risk of double-booking and communication errors Atomic inter-ward transfers with automatic bed state synchronization
Discharge Turnover Hours of turnover lag; beds sit idle Automated bed release upon discharge; instant sanitization records
Analytics & Reporting Manual periodic reports compiled after the fact Live Chart.js charts dynamically updating census metrics in real time

7.3 Rule-Based Smart Bed Allocation Engine

Implemented in backend/src/services/allocationService.ts, the allocation algorithm assigns numerical weights to clinical triage priorities:

Priority Weight (Wp): Emergency = 4 (Immediate trauma / life-threat) High = 3 (Urgent clinical oversight) Medium = 2 (Standard inpatient care) Low = 1 (Elective / minor observation)

The engine sorts waiting patients in descending order of priority weight, queries available beds in the patient's requested ward, falls back to Emergency/ICU beds for trauma cases if needed, marks the bed as Occupied, updates the patient's status to Admitted, logs the event, and writes changes to persistent storage.

7.4 In-Memory & JSON Persistent Data Architecture

The platform maintains an in-memory cache synchronized with backend/src/data/mockData.json. The initial dataset provides:

  • 250 Total Beds: General Ward (100), ICU (35), Emergency (40), Private Ward (45), Pediatric Ward (30). Breakdown: 170 Occupied, 65 Available, 10 Maintenance, 5 Reserved.
  • 193 Inpatients: 170 occupying active beds, 15 in the triage queue, and 8 historical discharges.
  • Audit Event Log: Real-time event log tracking admissions, transfers, and discharges.

7.5 Patient Flow & 4-Stage Kanban Workflow Engine

Patients are tracked across four clinical stages: Waiting for Admission $\rightarrow$ Admitted $\rightarrow$ Under Treatment $\rightarrow$ Ready for Discharge. The client renders an interactive four-column Kanban board with stage-specific action controls that update patient state via REST calls.

7.6 Automated Discharge & Dynamic Bed Recalculation

Confirming a patient discharge sets the patient's status to Discharged, timestamps dischargeDate, releases the assigned bed to Available, sets lastCleaned to the current time, logs a discharge event, and dynamically updates hospital occupancy and turnover metrics.

7.7 Chart.js Data Visualizations & Lucide Integration

The dashboard integrates Chart.js to render an interactive doughnut chart showing bed status distribution (with a center percentage display) and a grouped bar chart comparing occupied vs. available beds across all five wards. Lucide Icons provide clear visual cues across navigation items, stat cards, and modals.

7.8 Testing, Verification & End-to-End Test Suite

An automated test suite (test_suite.js) validated all 12 API endpoints, patient CRUD operations, smart allocation, bed transfers, and discharges against the live server, achieving a 100% pass rate with zero runtime errors.

9. Conclusion & Future Enhancements

9.1 Project Summary

The course project titled “Design and Development of a Smart Hospital Bed Allocation and Patient Flow Management System (MediPulse Flow)” successfully delivered a production-grade web application for real-time hospital administration. By replacing manual spreadsheets and phone coordination with an automated rule-based allocation engine and an interactive four-stage Kanban workflow, MediPulse Flow eliminates admission bottlenecks, prevents double-allocations, and accelerates patient flow.

The project met all engineering requirements:

  • A lightweight, responsive frontend built with HTML5, CSS3, and TypeScript / ES6+ JavaScript with Chart.js and Lucide Icons.
  • An Express.js REST API in TypeScript providing full CRUD capabilities for patients, beds, workflow stages, and census metrics.
  • An in-memory synchronized JSON storage engine (mockData.json) pre-populated with 250 beds and realistic patient records, eliminating external database server dependencies.
  • An automated integration test suite verifying all 12 API endpoints with a 100% pass rate.
  • Source code managed under Git and hosted on GitHub at https://github.com/Pranav9491/SESD-Project.

9.2 Future Enhancements

Future improvements planned for MediPulse Flow include:

  1. IoT Smart Bed Telemetry: Connecting physical pressure sensors to beds to detect patient occupancy and vacation automatically.
  2. Machine Learning Length of Stay (LoS) Prediction: Training regression models on diagnosis and vital signs data to predict discharge readiness days in advance.
  3. Role-Based Access Control (RBAC) & SSO: Implementing JWT/OAuth2 authentication with distinct permission scopes for triage nurses, ward supervisors, and chief medical officers.
  4. HL7 / FHIR Interoperability: Adding Fast Healthcare Interoperability Resources (FHIR) endpoints for bidirectional synchronization with external Electronic Health Record (EHR) systems.
